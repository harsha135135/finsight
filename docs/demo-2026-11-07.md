# FinSight demo on the real 3M FY2018 10-K (local Qwen, 2026-11-07)

Request through the API (`POST /research-jobs`) and the durable worker: *"Using 3M's FY2018 annual report, report
revenue, operating margin and capital expenditure. Show the calculations and cite each source."* Claude spend: $0.00.

**Source.** 10-K accession `0001558370-19-000470` (original, not amended), primary document sha256 `252d5b98ace7…`,
10.0 MB, parsed into 2,378 passages in 0.6 s. XBRL facts are taken from the same accession (as reported).

**Serving.** vLLM 0.33 on the PC through the SSH tunnel: `modelforge serve --compact-json --reasoning-parser qwen3
--max-model-len 6144` (FinSight serving; FinQA runs use the default protocol they were measured with).

**Evidence gaps and failures (all explicit):**

| Request | Outcome | Why |
|---|---|---|
| "How many employees did 3M have in Antarctica in FY2018?" | insufficient_evidence | no supported metric; no model call |
| "What was 3M's FY2031 revenue?" | insufficient_evidence | no 10-K for fiscal year 2031 |
| FY2018 net income, v1 | failed | value 5,349,000 (wrong scale) rejected: XBRL reports 5,349,000,000 |
| FY2018 net income, base + thinking | failed | empty `value` twice (greedy repair repeated the same output) |

**What the real filing exposed (fixed before these runs):**
1. Retrieval ranked accounting-standards prose above the income statement, and segment/geographic/quarterly
   tables share row labels with the consolidated statements. Ranking now prefers exact labels, clean fiscal-year
   headers and Item 8 statements.
2. Base Qwen refused "Net sales" as revenue; models returned metric names like "revenue for FY2018"; all models chose
   `insufficient_evidence` even with correct operands, because the prompt explained only that status. Prompt
   v1.1 groups evidence per metric with definitions and states when to answer; the schema limits metric and
   period to the requested values.
3. v1 emitted whitespace inside guided JSON until `max_tokens`; vLLM 0.33 only honours `disable_any_whitespace`
   server-wide, hence `--compact-json`.
4. A model labelled revenue's unit "ratio"; the unit is now derived from the cited operands.

**Not shown by this demo.** One company-year with three metrics is a smoke test, not an accuracy measurement; the
measured comparison is FinanceBench (Stage 7). v1 was trained on FinQA `answer-v4`, not this contract; its
net-income scale error is one example of what a FinSight-format evaluation must measure.

## The same demo from the Compose stack (Docker on the Mac, Qwen on the PC)

`docker compose up -d`; the worker container reaches vLLM at `host.docker.internal:8000` through the Mac's SSH tunnel
(the endpoint stays bound to 127.0.0.1 on the PC). Jobs submitted to the containerised API, model v1:

| Tunnel | Job | Outcome |
|---|---|---|
| up | `compose-tunnel-up-1`, `-up-2` | completed; revenue 32,765M, margin 22.0%, capex 1,577M, all agreeing with XBRL |
| closed | `compose-tunnel-down-2` | failed: "model server unavailable (ConnectError); resubmit when it is reachable" (no model call) |
| reopened | `compose-tunnel-up-3` | completed, same values |

Also verified in the containers: the filing download uses the SEC contact from `.env`; a SIGSTOPped worker was killed by
the watchdog after 30 s and replaced. (Reusing an idempotency key returns the original job, as designed; the down test
therefore uses a fresh key.)
